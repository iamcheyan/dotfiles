## 一、已确认缺陷（有复现证据）

### P0-1 `yanky.nvim` 配置了 `storage = "sqlite"`，但本机没有 libsqlite3 → 插件 setup 失败

- **位置**：`lua/plugins/yanky-substitute.lua:5-6,11`
- **代码**：
  ```lua
  dependencies = { "kkharji/sqlite.lua" },
  opts = { ring = { storage = "sqlite" } },
  ```
- **根因**：`sqlite.lua` 是 LuaJIT FFI 绑定，`defs.lua:36-45` 硬编码 Debian/RedHat 路径（`/usr/lib/x86_64-linux-gnu/libsqlite3.so` 等）。NixOS 上这些路径全不存在，`ffi.load` 失败。
- **复现**：
  ```
  yanky.setup(storage=sqlite) -> false
    sqlite/init.lua:66: loop or previous error loading module 'sqlite.db'
    sqlite/defs.lua:58: libsqlite3.so: 共有オブジェクトファイルを開けません
  ```
- **后果**：`yanky.history.setup()` 抛错 → `yanky.setup()` 在第 35 行中断 → **`preserve_cursor.setup()` 与 `highlight.setup()` 从未执行**：
  ```
  preserve_cursor.get_pos: false | attempt to call a nil value
  highlight.on_yank:     false | attempt to call a nil value
  ```
  这正是用户感受到的「各种各样的错误」。
- **已验证修复**：`storage = "shada"` → `yanky.setup: true`、`preserve_cursor.setup: true`、`highlight.setup: true`。
- **可选**：保留 sqlite 则需在 nixos-config 安装 sqlite 并设 `vim.g.sqlite_clib_path`（须为 x86-64 库；nix store 里同时存在 32 位构建，选错会报「間違った ELF」）。

### P0-2 `<leader>st` / `<leader>sT` 绑定了不存在的命令 `:TodoPicker`

- **位置**：`lua/plugins/todo-comments.lua:22-23`
- **根因**：上游 `todo-comments.nvim` 只提供 `TodoQuickFix` / `TodoLocList` / `TodoTelescope` / `TodoFzfLua` / `TodoTrouble`（`plugin/todo.vim:1-5`），**没有 `TodoPicker`**。
- **复现**：
  ```
  :TodoPicker exists: 0   (TodoQuickFix=2)
  运行 :TodoPicker -> E492: エディタのコマンドではありません
  Snacks.picker.pick('todo') -> true   ← 可用的替代
  ```
- **修复**：改用 `function() Snacks.picker.pick("todo") end` 或 `<cmd>TodoQuickFix<cr>`。

### P0-3 `<leader>fC` 调用已删除的 Telescope

- **位置**：`lua/config/keymaps.lua:25-34`
- **根因**：LazyVim 时代遗留。`telescope.nvim` 未安装（不在 lazy-lock.json 的 39 项中，也不在磁盘上）。
- **复现**：按 `<leader>fC` → `E5108: module 'telescope.builtin' not found`。
- **修复**：改用 `Snacks.picker.files({ dirs = { "~/dotfiles", "~/.config/nvim" }, title = "常用配置文件" })`，或删除该键位。

### P0-4 `<leader>fu`（dos2unix）在本机必然报错

- **位置**：`lua/config/keymaps.lua:40-46`
- **根因**：`dos2unix` 未安装；且 `vim.fn.system()` 在可执行文件缺失时**抛错**而非返回错误码，而 `notify` 无条件执行（失败也报成功）。
- **复现**：`system() missing exe: false  Vim:E475: ... 'dos2unix' is not executable`
- **修复**：先判 `vim.fn.executable("dos2unix") == 1`，否则 notify 警告并 return；用 `vim.system()` 检查 exit code 再 notify。

### P1-1 Select 模式反斜杠会插入两个 `\`

- **位置**：`lua/config/keymaps.lua:203-207`
- **代码**：`vim.keymap.set("s", char, '<c-o>"_c' .. (char == "\\" and "\\\\" or char), ...)`
- **根因**：Lua 字符串 `"\\\\"` 是**两个**反斜杠字符，而其它分支只加一个。实测 `#rhs == 10`，rhs=`<c-o>"_c\\`。
- **复现**：
  ```
  select 模式输入 \ -> "\\\\f"  (两个反斜杠)
  select 模式输入 X -> "Xf"      (一个，正常)
  ```
- **影响**：补全占位符/snippet/`gh` 等 Select 场景下输入 Windows 路径、LaTeX、正则必然多一个 `\`。
- **修复**：`(char == "\\" and "\\" or char)`。

### P1-2 `<leader>cf` 与 `<leader>cd` 被静默覆盖

- **位置**：`lua/config/keymaps.lua:13,21` 覆盖 `lua/config/keymaps-lazyvim.lua:142,158`
- **复现**：`<leader>cf desc=Copy file (relative path)`、`<leader>cd desc=Copy directory` —— LazyVim 语义的「格式化」和「诊断浮窗」已不可达。
- **说明**：`lazy.lua:106-109` 先加载 `keymaps-lazyvim` 再加载 `keymaps`，后者无条件覆盖，且无注释标明是有意冲突。格式化仍可用 `<leader>fo` / `<leader>F`。
- **修复**：删除或改绑冲突项，并加注释说明取舍。

### P1-3 `vim.opt.showtabline = 0` 无效

- **位置**：`lua/config/options.lua:193`
- **根因**：bufferline 默认 `auto_toggle_bufferline = true`（`config.lua:664`），其 `toggle_bufferline()`（`bufferline.lua:90-94`）在每次渲染 tabline 时改写 `vim.o.showtabline`。
- **复现**：启动时 `showtabline = 2`（非 0）。
- **修复**：bufferline opts 加 `options = { auto_toggle_bufferline = false }`，或改注释为 `showtabline = 1`。

### P1-4 `vim.g.autoformat = false` 与格式化键位互相矛盾

- **位置**：`lua/plugins/conform.lua:41` 设 `vim.g.autoformat = false`；`keymaps-lazyvim.lua:142-146` 的格式化回调却用 `if vim.g.autoformat ~= false then` 作门槛。
- **后果**：该回调永不生效（`<leader>cf` 又被 P1-2 覆盖），实际可用的是 `<leader>fo`。
- **修复**：去掉 autoformat 门槛，或改绑 `require("conform").format(...)`。

### P1-5 LSP 诊断禁用是重复且部分无效的

- **位置**：`lua/plugins/lsp.lua:40` 在 `on_attach` 内写 `client.handlers["textDocument/publishDiagnostics"]`；另有 `disable-diagnostics.lua` 与 `options.lua` 全局禁用。
- **实测**：`on_attach` 完整跑完（`gd/K/gI/gy/gK/<C-k>/<leader>ca/<leader>cr` 全部建立，`formatexpr` 已设），**未观察到崩溃**。该行属死代码；`client.handlers` 应在 client 构造时（`vim.lsp.config` 表内）提供。
- **修复**：删除该行（全局诊断已在 `options.lua` 关闭）。
