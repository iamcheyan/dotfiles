# 浮窗 UI 设计与实现

这份说明记录 Neovim 自定义浮窗的视觉约定、布局方法和实现边界。新增确认框、菜单、预览窗等界面时先看这里，保持不同 UI 的尺寸、间距和配色一致。

## 当前实现

Noice 的 `:q` 未保存确认框是一个屏幕中央的卡片：标题先说明要做什么，文件名单独突出显示，完整目录另起一行；分隔线下方排列操作按钮，并标出默认选项。路径按显示宽度换行，处理中文等宽字符时使用 Neovim 的 `strdisplaywidth`、`strcharpart`，不要用字节数截断 UTF-8 字符。

配色跟随当前 colorscheme。使用内置 `blue` 主题时，卡片直接采用 `Normal` 的深蓝背景，标题与文件名沿用 Nostalgia 调色板的黄／青色，默认操作用蓝绿色强调，其他按钮保持普通文字样式。其他主题使用通用的深色或浅色样式。新增 UI 时优先读取 `Normal` 和已有主题调色板中的语义颜色，不要另造一套与编辑区冲突的背景色。

实际配置分在两个文件：

- `lua/plugins/noice.lua` 设置 Noice 的底部命令行、确认视图的宽度、位置和边框。
- `lua/config/confirm_dialog.lua` 负责解析确认消息、构造卡片内容、分行按钮和语义高亮。

确认格式只改变显示内容，按键和确认结果仍交给 Neovim 原生 `confirm()` 处理。遇到不认识的提示格式时保留原始消息，不自行吞掉用户输入或改变操作结果。

同一条确认重复出现时（例如对同一个未保存文件再次执行 `:q`），Neovim 可能只发出 `cmdline_show` 的选项提示，不再发送完整问题。`confirm_dialog.lua` 会缓存最近一次完整确认内容，并且只有在 Y／N／C 选项签名相同时才把重复提示重新放进卡片；这样保留文件路径，也不会把普通输入提示误判为确认框。

重复提示必须先同步移除历史记录中的旧确认消息：使用 `Manager.get(filter, { history = true })` 查找，再调用 `Manager.remove`。Noice 的 router 显示消息后会清空待处理队列，屏幕上的消息仍保留在 history 中；只查默认队列会漏掉旧卡片。原生确认收到鼠标按下或释放后可能重新发出提示，而旧消息的移除是异步的，遗漏清理会使卡片暂时显示两份内容，高度翻倍，居中位置随之上下跳动。修复验证应记录点击前后的窗口尺寸和位置，并检查取消后再次执行 `:q` 的情况，不能只检查最终静止画面。

确认卡片没有文本输入光标。Noice 的确认分支跳过普通命令行的光标定位，输入 `:q` 后可能把终端光标留在底部命令行位置，覆盖状态栏文字旁边的空格。卡片显示期间保存原有 `guicursor` 并使用 `blend = 100` 的专用光标高亮隐藏它；退出确认后恢复原值。鼠标造成的提示重发仍处于 `mode(1) == "r?"`，此时保持隐藏，避免光标闪现。不能通过更改 Git 状态栏背景修复这个终端光标残留。

### 复用确认框的光标处理

实现入口在 `confirm_dialog.lua` 的 `setup()` 和 `highlights()`：

1. 定义 `ConfirmDialogHiddenCursor = { blend = 100, nocombine = true }`，并在切换配色后重新定义。
2. 在完整确认消息和缓存确认提示两条显示分支中，先保存原有 `guicursor`，再设置为 `a:ConfirmDialogHiddenCursor`。重复提示不能覆盖第一次保存的值。
3. 包装 `Cmdline.on_hide` 时先调用原处理函数，再通过 `vim.schedule` 检查模式。只有离开 `r?` 确认模式时才恢复保存的值并清空缓存；鼠标按下、释放产生的短暂隐藏不应恢复光标。

2026-10-09 验证记录：连续 15 次弹窗外鼠标按下／释放，卡片无重绘、尺寸与位置稳定，光标持续隐藏；取消后原有光标设置完整恢复。未保存文件执行 `:q`、取消后再次执行 `:q`，以及 Y／N／C／Enter 的原生操作结果均通过检查，用户确认绿色块已消失。

## 浮窗视觉约定

- 先明确窗口在界面中的位置和用途，再定宽高。居中弹窗用 editor 相对定位及 `row = "50%"`、`col = "50%"`；NUI 会按窗口尺寸计算居中位置。
- 给文本设最大宽度和自动换行，让长路径、长说明在卡片内部折行。终端较窄时，宽度应跟着可用列数收缩。
- 把标题、正文、路径、说明和按钮分开排布；用留白、分隔线和对齐表达层级，避免一行塞满提示和操作项。
- 高亮使用有含义的组名（例如标题、路径、默认按钮、次要按钮），并为深浅背景提供可读配色。换主题时重新应用自定义高亮。
- 默认操作要一眼可见；危险或不可逆操作可用警示色。所有按钮保留文字和按键提示，颜色不能成为唯一提示。
- 保持交互动作原生：UI 负责呈现，原命令或回调负责执行。除非明确设计了新的交互，不要让视觉按钮接管原有快捷键语义。

## 全局浮窗样式的边界

`lua/config/float_style.lua` 会包装 `nvim_open_win`，为普通浮窗统一补边框和高亮。这个入口影响全局，因此修改前要确认目标窗口由谁管理：

- NUI 可能用独立窗口绘制边框；不要再给它内部窗口重复套一层边框。
- Noice 的底部命令行虽然以浮窗绘制，但必须保持无边框。给它补边框会在命令行出现前闪出一个空框。当前全局样式会跳过 `filetype == "noice"` 的窗口。
- Snacks Picker 有自己的窗口与配色规则，保留现有排除逻辑。
- backdrop 或其他不可交互的辅助窗口要单独判断，避免把边框和颜色覆写到遮罩层。

给新 UI 加全局例外时尽量按明确的 `filetype` 或窗口用途匹配，避免用过宽的条件影响其他插件。确认新界面是否有多层窗口，以及 `winhighlight` 是否会被全局包装器覆盖。

## 验证交互与外观

浮窗代码容易出现“先画后改”的闪烁，只检查最终窗口属性不够。用嵌入式 Neovim 接上 UI，记录 `nvim_open_win` 的参数并检查重绘内容，可以发现短暂出现的旧边框。

增加或调整浮窗后，至少检查：

1. 打开前、打开时和关闭后的窗口数量与位置；无关窗口不应闪现。
2. 长文本和窄终端下的换行、最大尺寸与屏幕边界。
3. 默认、次要、危险操作的颜色层级，以及深浅主题下的文字对比度。
4. 键盘和鼠标操作仍触发原来的行为；确认类提示逐个验证默认键、其他选项和取消。
5. 多次打开、关闭及切换 colorscheme 后，边框和高亮仍正确。

相关代码：`lua/config/float_style.lua`、`lua/config/confirm_dialog.lua`、`lua/plugins/noice.lua`；菜单实现与 UI 检查参见 `lua/config/popup_menu.lua` 和 `tests/popup_menu_ui_spec.py`。
