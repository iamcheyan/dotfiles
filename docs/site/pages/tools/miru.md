> 摘要：miru 是用 Go 写的终端文件查看器，Markdown 走 glamour，源码与配置文件走 chroma，按 b 在浏览器里打开带 mermaid 的 HTML 预览。

# miru

## 用途

`miru` 是一个终端文件查看器，把两种场景合并成一个命令：

- **Markdown** — TUI 里用 glamour 渲染 ANSI，按 `b` 在浏览器里打开 goldmark 生成的 HTML 页面，支持 mermaid 图表。
- **源码 / 配置文件** — TUI 里用 chroma 做语法高亮，带行号；按 `b` 在浏览器里打开深色主题的 HTML 页面。

本仓库用它作为 `bat` / `glow` 之外的第三种查看器：需要看 Markdown 里的 mermaid 图，或者需要在浏览器里看源码时用 `miru`。

## 来源与安装

| 项目 | 说明 |
|---|---|
| 仓库 | `hiro4ta/miru`（Go，MIT） |
| 安装器 | `scripts/install/install_miru.sh` |
| 二进制 | 静态二进制，无 Go 工具链依赖 |
| 配置 | `~/.config/miru/config.json`（仅 theme 字段） |

```bash
# 一键安装
bash scripts/install/install_miru.sh

# 或直接用上游 bootstrap
curl -fsSL https://raw.githubusercontent.com/hir4ta/miru/main/install.sh | sh

# 或 Homebrew
brew install hir4ta/tap/miru

# 或 go install
go install github.com/hir4ta/miru/cmd/miru@latest
```

安装器会下载对应平台的 tarball，校验 SHA-256，然后调用 `miru install`（Bubble Tea 自安装 UI）把二进制装到 `~/.local/bin` 并把 PATH 写进 shell rc。

## 基本用法

```bash
miru README.md           # Markdown（glamour）
miru main.go             # 源码（chroma + 行号）
miru config.yaml         # 配置文件（chroma）
miru Dockerfile          # 按文件名识别类型（chroma）
miru --theme gruvbox README.md
miru --list-themes
miru version
```

扩展名决定走哪条路径：`.md` / `.markdown` → Markdown；其余 → Source/Config。

## 浏览器预览（b）

按 `b` 启动一个 loopback HTTP 服务器（`127.0.0.1:<random>`），作用域是文件所在项目的根目录（向上找到 `.git`、`go.mod`、`package.json`、`Cargo.toml`、`pyproject.toml` 之一；找不到就用文件自身目录），在默认浏览器里打开渲染后的页面。TUI 退出时服务器自动停止。

三种渲染：

| 类型 | 渲染方式 |
|---|---|
| Markdown | goldmark + GFM，github-markdown.css，mermaid.js（CDN） |
| 源码/配置 | chroma 带行号，深色主题 |
| 图片/二进制 | 原样服务，带正确 Content-Type |

相对链接（如 `[guide](./docs/guide.md)`）会被跟踪，点击后重新渲染目标文件。

**安全注意**：Markdown 里允许 raw HTML，mermaid 用 `securityLevel: "loose"`，和 Obsidian / VS Code 预览一致。未信任的 Markdown 不要用 `b` 打开。TUI 视图本身是纯 ANSI 文本，无脚本、无远程请求。

## 与 bat / glow 的分工

| | bat | glow | miru |
|---|---|---|---|
| Markdown | 语法高亮 | 终端渲染 | TUI glamour + 浏览器 HTML + mermaid |
| 源码 | 语法高亮 | 不支持 | chroma + 行号 + 浏览器预览 |
| 交互 | 无 | 无 | 滚动、跳转、主题切换、浏览器打开 |
| 依赖 | 无 | 无 | 无（静态二进制） |

`bat` 适合快速看文件内容，`glow` 适合终端里读 Markdown，`miru` 适合需要跳转、主题切换或浏览器预览时。

## 排错

- `miru: command not found` — Zinit / 安装器没装。`command -v miru` 确认，或直接跑 bootstrap。
- 图片 / mermaid 不显示 — 浏览器里开 DevTools 看 CSP / 网络。miru 的 CSP 是 per-render nonce，脚本只允许 nonce + strict-dynamic。
- 主题不生效 — 优先级链检查：`--theme` > `$MIRU_THEME` > 配置文件 > `claude`。
- `miru update` 失败 — 网络问题或 checksum 不匹配。`miru update --help` 查看选项。
- 配置文件路径 — `$XDG_CONFIG_HOME/miru/config.json` 或 `~/.config/miru/config.json`。

# miru

## Purpose

`miru` is a terminal file viewer that merges two scenarios into one command:

- **Markdown** — glamour renders ANSI in the TUI; pressing `b` opens an HTML page generated by goldmark in the browser, with mermaid diagram support.
- **Source / config files** — chroma does syntax highlighting with line numbers in the TUI; pressing `b` opens an HTML page with a dark theme in the browser.

This repository uses it as a third viewer alongside `bat` / `glow`: use `miru` when you need to see mermaid diagrams inside Markdown, or need to view source code in the browser.

## Source and install

| Item | Notes |
|---|---|
| Repository | `hiro4ta/miru` (Go, MIT) |
| Installer | `scripts/install/install_miru.sh` |
| Binary | static binary, no Go toolchain dependency |
| Config | `~/.config/miru/config.json` (theme field only) |

```bash
# 一键安装
bash scripts/install/install_miru.sh

# 或直接用上游 bootstrap
curl -fsSL https://raw.githubusercontent.com/hir4ta/miru/main/install.sh | sh

# 或 Homebrew
brew install hir4ta/tap/miru

# 或 go install
go install github.com/hir4ta/miru/cmd/miru@latest
```

The installer downloads the tarball for your platform, verifies the SHA-256, then calls `miru install` (a Bubble Tea self-install UI) to put the binary in `~/.local/bin` and write the PATH entry into your shell rc.

## Basic usage

```bash
miru README.md           # Markdown（glamour）
miru main.go             # 源码（chroma + 行号）
miru config.yaml         # 配置文件（chroma）
miru Dockerfile          # 按文件名识别类型（chroma）

```

The file extension decides which path is taken: `.md` / `.markdown` → Markdown; everything else → Source/Config.

## Browser preview (b)

Pressing `b` starts a loopback HTTP server (`127.0.0.1:<random>`) scoped to the root of the project containing the file (found by walking up to `.git`, `go.mod`, `package.json`, `Cargo.toml` or `pyproject.toml`; the file's own directory is used if none is found) and opens the rendered page in the default browser. The server stops automatically when the TUI exits.

Three kinds of rendering:

| Type | Rendering |
|---|---|
| Markdown | goldmark + GFM, github-markdown.css, mermaid.js (CDN) |
| Source/config | chroma with line numbers, dark theme |
| Images/binaries | served as-is with the correct Content-Type |

Relative links (such as `[guide](./docs/guide.md)`) are followed; clicking one re-renders the target file.

**Security note**: raw HTML is allowed inside Markdown, and mermaid uses `securityLevel: "loose"`, consistent with Obsidian / VS Code preview. Don't open untrusted Markdown with `b`. The TUI view itself is pure ANSI text — no scripts, no remote requests.

## Division of labor with bat / glow

| | bat | glow | miru |
|---|---|---|---|
| Markdown | syntax highlighting | terminal rendering | TUI glamour + browser HTML + mermaid |
| Source | syntax highlighting | not supported | chroma + line numbers + browser preview |
| Interactivity | none | none | scrolling, jumping, theme switching, open in browser |
| Dependencies | none | none | none (static binary) |

`bat` is for quickly reading file contents, `glow` for reading Markdown in the terminal, `miru` when you need jumping, theme switching or a browser preview.

## Troubleshooting

- `miru: command not found` — not installed by Zinit / the installer. Confirm with `command -v miru`, or just run the bootstrap.
- Images / mermaid don't show — open DevTools in the browser and check CSP / network. miru's CSP is a per-render nonce; scripts only allow nonce + strict-dynamic.
- Theme not taking effect — check the precedence chain: `--theme` > `$MIRU_THEME` > config file > `claude`.
- `miru update` fails — a network problem or checksum mismatch. See `miru update --help` for options.
- Config file path — `$XDG_CONFIG_HOME/miru/config.json` or `~/.config/miru/config.json`.

## ブラウザプレビュー（b）

`b` を押すとループバック HTTP サーバー（`127.0.0.1:<random>`）が起動します。スコープはファイルが属するプロジェクトのルート（上へ辿って `.git`、`go.mod`、`package.json`、`Cargo.toml`、`pyproject.toml` のいずれかを見つける。見つからなければファイル自身のディレクトリ）で、描画済みページがデフォルトブラウザで開きます。TUI を終了するとサーバーは自動的に停止します。

3 種類の描画：

| 種類 | 描画方法 |
|---|---|
| Markdown | goldmark + GFM、github-markdown.css、mermaid.js（CDN） |
| ソース/設定 | chroma で行番号付き、ダークテーマ |
| 画像/バイナリ | 適切な Content-Type 付きでそのまま配信 |

相対リンク（`[guide](./docs/guide.md)` など）は辿られ、クリックすると対象ファイルを再描画します。

**セキュリティ注記**：Markdown 内では生 HTML が許可され、mermaid は `securityLevel: "loose"` を使います。これは Obsidian / VS Code のプレビューと同じ挙動です。信頼できない Markdown を `b` で開かないでください。TUI 表示自体は純粋な ANSI テキストで、スクリプトもリモートリクエストもありません。

## トラブルシュート

- `miru: command not found` — Zinit / インストーラでインストールされていません。`command -v miru` で確認するか、bootstrap を直接実行します。

- `miru update` が失敗する — ネットワークの問題かチェックサム不一致です。オプションは `miru update --help` を参照します。
- 設定ファイルのパス — `$XDG_CONFIG_HOME/miru/config.json` または `~/.config/miru/config.json`。
