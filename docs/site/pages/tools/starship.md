> 摘要：Starship 是跨 shell 的提示符渲染器，本仓库用它生成两行提示符。

# Starship

## 用途

Starship 读取当前目录、Git 状态、语言运行时版本等信息，输出一个提示符字符串。它本身不绑定某个 shell，通过 `starship init zsh` 生成的代码在每个提示符前被调用。

本仓库的提示符、颜色、图标全部由 `config/starship/starship.toml` 定义。

## 来源与安装

| 项目 | 说明 |
|---|---|
| 来源 | Zinit，按 OS/CPU 选择 GitHub Release 包 |
| 加载位置 | `plugins/prompt/prompt.zsh` |
| 配置文件 | `config/starship/starship.toml` → `~/.config/starship.toml` |

```zsh
local _starship_bpick
if [[ "$OSTYPE" == "darwin"* ]]; then
  if [[ "$(uname -m)" == "arm64" ]]; then
    _starship_bpick="*aarch64-apple-darwin.tar.gz"
  else
    _starship_bpick="*x86_64-apple-darwin.tar.gz"
  fi
else
  if [[ "$(uname -m)" == "aarch64" ]] || [[ "$(uname -m)" == "arm64" ]]; then
    _starship_bpick="*aarch64-unknown-linux-musl.tar.gz"
  else
    _starship_bpick="*x86_64-unknown-linux-musl.tar.gz"
  fi
fi

zinit ice as"command" from"gh-r" bpick"${_starship_bpick}" pick"starship" sbin"starship"
zinit light starship/starship

if command -v starship >/dev/null 2>&1; then
  eval "$(starship init zsh)"
fi
```

Linux 用 musl 版本，静态链接，不依赖系统 glibc 版本。

## 提示符结构

```toml
format = """
$hostname$directory$git_branch$git_status$python$nodejs$rust$golang$java$package$docker_context$kubernetes$aws$terraform$time
$character"""

right_format = """$status$cmd_duration$jobs"""
```

第一行是一串信息模块，第二行只有 `$character`（`❯` 符号）。右侧单独一行显示退出状态、耗时、后台任务数。

## 各模块的配置

### directory

```toml
[directory]
truncation_length = 3
truncate_to_repo = true
style = "bold #50fa7b"
```

路径最多显示 3 层，进入 Git 仓库后只显示仓库相对路径。这解决了「路径太长把提示符撑爆」的问题。

### git_branch / git_status

```toml
[git_branch]
symbol = " "
style = "bold purple"

[git_status]
ahead = "⇡${count}"
behind = "⇣${count}"
diverged = "⇕⇡${ahead_count}⇣${behind_count}"
staged = "[+${count}](bold green)"
modified = "[~${count}](bold yellow)"
untracked = "[?${count}](bold red)"
deleted = "[-${count}](bold red)"
stashed = "[*${count}](bold blue)"
```

用符号和颜色区分六种状态：已暂存、已修改、未跟踪、已删除、stash、领先/落后远端。

### 语言模块

| 模块 | 触发文件 |
|---|---|
| python | `requirements.txt`、`pyproject.toml`、`setup.py`、`.python-version`、`Pipfile`、`.venv/`、`venv/` |
| nodejs | `package.json` |
| rust | `Cargo.toml` |
| golang | `go.mod` |
| java | `pom.xml`、`build.gradle` |

python 模块还会显示虚拟环境名：

```toml
[python]
format = '[$symbol(${version} )(\($virtualenv\) )](bold yellow)'
```

### 云与基础设施

| 模块 | 显示内容 |
|---|---|
| docker_context | 非默认 Docker context 名 |
| kubernetes | context 和 namespace |
| aws | profile 和 region |
| terraform | workspace |

这些默认是 `disabled = false`，只要检测到对应配置就显示。如果你不用它们，可以在 `local/` 里覆盖成 `disabled = true`。

### cmd_duration

```toml
[cmd_duration]
min_time = 2_000
format = "[$duration](bold yellow) "
```

只显示超过 2 秒的命令，避免每条命令都出现 `0ms`。

### hostname

```toml
[hostname]
ssh_only = true
format = "[$hostname@ssh]($style) "
```

只在 SSH 会话显示，提示你「现在操作的是远端机器」。

## 常用命令

```bash
starship explain              # 解释当前提示符每个模块
starship prompt               # 打印当前提示符
starship module directory     # 单独渲染某模块
starship config               # 打开配置文件
starship preset --list        # 列出内置预设
starship preset nerd-font-symbols -o ~/.config/starship.toml
starship timings              # 各模块耗时（排查慢）
```

`starship explain` 是排查提示符问题最快的手段：它会逐模块说明「为什么显示」或「为什么不显示」。

## 性能

Starship 每次渲染提示符都会执行，模块越多越慢。排查方法：

```bash
starship timings
```

输出每个模块的耗时。常见慢项：

- `git_status` 在大仓库里慢（要遍历所有变更文件）
- `kubernetes` / `aws` 要读配置文件和执行外部命令
- `cmd_duration` 依赖 shell hook

如果提示符有明显延迟，先关掉不用的云模块。

## Nerd Font 依赖

配置里大量使用 Nerd Font 私有区字符（`❯`、``、``、`󰏗`）。终端字体必须是 Nerd Font，否则显示成方框。

本仓库用 Meslo Nerd Font，由 `scripts/install/install_font.sh` 安装。装完后在终端设置里选择 `MesloLGS Nerd Font`。

## 与 Ghostty 的关系

Ghostty 提供字体和配色，Starship 提供文字内容。两者独立：换 Ghostty 主题不影响 Starship 输出，但字体缺失会让图标变成方块。

## 排错

**提示符是默认的 `%`**：`starship init zsh` 没执行。检查 `plugins/prompt/prompt.zsh` 是否被 source，以及它是否在 `[[ -t 1 ]]` 条件内被跳过（非交互场景）。

**图标显示成方框**：字体不对。装 Meslo Nerd Font 并在终端里选中。

**Git 状态不显示**：不在仓库内，或 `git_status` 被 `disabled = true`。

**提示符有延迟**：`starship timings` 找出慢模块，在 `local/` 里关掉。

**Python 版本不显示**：当前目录没有触发文件。`starship explain` 会说明。

# Starship

## Purpose

Starship reads information such as the current directory, Git status, and language runtime versions, then outputs a prompt string. It is not tied to a particular shell; code generated by `starship init zsh` runs before each prompt.

The prompt, colors, and icons in this repository are all defined in `config/starship/starship.toml`.

## Source and installation

| Item | Description |
|---|---|
| Source | Zinit, selecting a GitHub Release package by OS/CPU |
| Load location | `plugins/prompt/prompt.zsh` |
| Configuration file | `config/starship/starship.toml` → `~/.config/starship.toml` |

Linux uses the musl version, which is statically linked and does not depend on the system glibc version.

## Prompt structure

The first line is a sequence of information modules, and the second line contains only `$character` (the `❯` symbol). The right side displays the exit status, duration, and number of background jobs on a separate line.

## Module configuration

### directory

The path displays at most 3 levels. Inside a Git repository, only the path relative to the repository is shown. This prevents “the path being too long and stretching the prompt beyond the screen.”

### git_branch / git_status

Symbols and colors distinguish six kinds of state: staged, modified, untracked, deleted, stashed, and ahead/behind the remote.

### Language modules

| Module | Trigger files |
|---|---|
| python | `requirements.txt`, `pyproject.toml`, `setup.py`, `.python-version`, `Pipfile`, `.venv/`, `venv/` |
| nodejs | `package.json` |
| rust | `Cargo.toml` |
| golang | `go.mod` |
| java | `pom.xml`, `build.gradle` |

The python module also displays the virtual environment name.

### Cloud and infrastructure

| Module | Displayed content |
|---|---|
| docker_context | Non-default Docker context name |
| kubernetes | Context and namespace |
| aws | Profile and region |
| terraform | Workspace |

These are enabled by default and appear when the corresponding configuration is detected. If you do not use them, override them to `disabled = true` in `local/`.

### cmd_duration

Only commands that take more than 2 seconds are displayed, avoiding `0ms` on every command.

### hostname

Only shown in SSH sessions, to remind you that “you are working on a remote machine.”

## Common commands

`starship explain` is the quickest way to troubleshoot prompt issues: it explains module by module “why it is shown” or “why it is not shown.”

## Performance

Starship runs every time the prompt is rendered, so more modules make it slower. Check each module's duration with `starship timings`. Common slow modules:

- `git_status` is slow in large repositories because it must traverse all changed files.
- `kubernetes` / `aws` read configuration files and run external commands.
- `cmd_duration` depends on a shell hook.

If the prompt has noticeable latency, first disable cloud modules you do not use.

## Nerd Font dependency

The configuration uses many Nerd Font private-use characters (`❯`, ``, ``, `󰏗`). The terminal font must be a Nerd Font; otherwise these appear as boxes.

This repository uses Meslo Nerd Font, installed by `scripts/install/install_font.sh`. After installation, select `MesloLGS Nerd Font` in the terminal settings.

## Relationship with Ghostty

Ghostty provides the font and colors, while Starship provides the text content. They are independent: changing the Ghostty theme does not affect Starship output, but a missing font makes icons appear as boxes.

## Troubleshooting

**The prompt is the default `%`**: `starship init zsh` did not run. Check whether `plugins/prompt/prompt.zsh` is sourced and whether it is skipped by the `[[ -t 1 ]]` condition in non-interactive contexts.

**Icons appear as boxes**: The font is incorrect. Install Meslo Nerd Font and select it in the terminal.

**Git status is not shown**: You are not in a repository, or `git_status` is set to `disabled = true`.

**The prompt is slow**: Use `starship timings` to find slow modules and disable them in `local/`.

**The Python version is not shown**: There is no trigger file in the current directory. `starship explain` will explain why.

# Starship

## 用途

Starship は現在のディレクトリ、Git の状態、言語ランタイムのバージョンなどを読み取り、プロンプト文字列を出力します。特定のシェルに依存せず、`starship init zsh` が生成するコードが各プロンプトの前に実行されます。

このリポジトリのプロンプト、色、アイコンはすべて `config/starship/starship.toml` で定義しています。

## 入手元とインストール

| 項目 | 説明 |
|---|---|
| 入手元 | OS/CPU に応じて GitHub Release パッケージを選ぶ Zinit |
| 読み込み場所 | `plugins/prompt/prompt.zsh` |
| 設定ファイル | `config/starship/starship.toml` → `~/.config/starship.toml` |

Linux では musl 版を使います。静的リンクされているため、システムの glibc バージョンに依存しません。

## プロンプトの構成

1行目には情報モジュールが並び、2行目には `$character`（`❯` 記号）だけが表示されます。右側には終了状態、実行時間、バックグラウンドジョブ数が独立した行に表示されます。

## 各モジュールの設定

### directory

パスは最大3階層まで表示します。Git リポジトリ内ではリポジトリからの相対パスだけを表示します。これにより「パスが長すぎてプロンプトが画面からはみ出す」問題を防ぎます。

### git_branch / git_status

記号と色で、ステージ済み、変更済み、未追跡、削除済み、stash、リモートより進んでいる／遅れている状態の6種類を区別します。

### 言語モジュール

| モジュール | 検出ファイル |
|---|---|
| python | `requirements.txt`、`pyproject.toml`、`setup.py`、`.python-version`、`Pipfile`、`.venv/`、`venv/` |
| nodejs | `package.json` |
| rust | `Cargo.toml` |
| golang | `go.mod` |
| java | `pom.xml`、`build.gradle` |

python モジュールは仮想環境名も表示します。

### クラウドとインフラ

| モジュール | 表示内容 |
|---|---|
| docker_context | 既定以外の Docker context 名 |
| kubernetes | context と namespace |
| aws | profile と region |
| terraform | workspace |

これらは既定で有効で、対応する設定が検出されると表示します。使わない場合は `local/` で `disabled = true` に上書きできます。

### cmd_duration

2秒を超えるコマンドだけを表示するため、すべてのコマンドに `0ms` が出ることを防ぎます。

### hostname

SSH セッションでのみ表示し、「現在はリモートマシンを操作している」と分かるようにします。

## よく使うコマンド

プロンプトの問題を調べるには `starship explain` が最も手早い方法です。各モジュールについて「なぜ表示されるか」「なぜ表示されないか」を説明します。

## パフォーマンス

Starship はプロンプトを描画するたびに実行されるため、モジュールが多いほど遅くなります。`starship timings` で各モジュールの所要時間を確認します。遅くなりやすい例は次のとおりです。

- `git_status` は変更ファイルをすべて走査するため、大きなリポジトリでは遅くなります。
- `kubernetes` / `aws` は設定ファイルを読み、外部コマンドを実行します。
- `cmd_duration` はシェルフックに依存します。

プロンプトに目立つ遅延がある場合は、まず使っていないクラウドモジュールを無効にします。

## Nerd Font の依存

設定では Nerd Font の私用領域文字（`❯`、``、``、`󰏗`）を多数使います。端末フォントが Nerd Font でない場合、文字が四角で表示されます。

このリポジトリでは `scripts/install/install_font.sh` で Meslo Nerd Font をインストールします。インストール後、端末設定で `MesloLGS Nerd Font` を選びます。

## Ghostty との関係

Ghostty はフォントと配色を提供し、Starship はテキスト内容を提供します。両者は独立しており、Ghostty のテーマを変えても Starship の出力には影響しません。ただし、フォントがないとアイコンが四角で表示されます。

## トラブルシューティング

**既定の `%` プロンプトが表示されます**：`starship init zsh` が実行されていません。`plugins/prompt/prompt.zsh` が source されるか、非対話環境で `[[ -t 1 ]]` 条件によりスキップされていないか確認します。

**アイコンが四角で表示されます**：フォントが正しくありません。Meslo Nerd Font をインストールして端末で選択します。

**Git の状態が表示されません**：リポジトリ内にいないか、`git_status` が `disabled = true` になっています。

**プロンプトに遅延があります**：`starship timings` で遅いモジュールを特定し、`local/` で無効にします。

**Python のバージョンが表示されません**：現在のディレクトリに検出対象ファイルがありません。`starship explain` で理由を確認できます。
